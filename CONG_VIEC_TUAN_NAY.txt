QUY TẮC CHUNG (ai cũng phải đọc trước khi làm)
--------------------------------------------------------------------------------
1. Trước khi bắt đầu:
       git switch main
       git pull
       git switch -c <nhanh-cua-ban>        (tên nhánh ghi ở từng việc bên dưới)

2. Đọc code trước: code/include/rabbit.h (giao diện lớp RabbitCipher) và chạy thử:
       cd code
       mingw32-make test
   Mở file code/output/test_vectors_log.txt để xem từng bước tính toán.

3. Commit nhỏ, mỗi commit một thay đổi có nghĩa, message tiếng Việt không dấu, ví dụ:
       git commit -m "test(key): them test vector RFC A.1 so 3"
   Không tạo commit rỗng, không commit file .exe hay file trong code/output/.

4. Trước khi push: "mingw32-make test" phải PASS hết, build không có warning.

5. Push nhánh, mở Pull Request vào main, nhờ 1 người khác review.
   Khi merge chọn "Create a merge commit", KHÔNG chọn "Squash and merge".

6. Nếu file test mới cần chạy cùng "mingw32-make test": thêm tên file (không có .cpp)
   vào dòng TESTS = ... trong code/Makefile. Nhiều người cùng sửa dòng này nên khi
   merge có thể bị xung đột: chỉ cần giữ lại tên test của TẤT CẢ mọi người.

7. Mỗi file test là một chương trình có hàm main(): in PASS/FAIL cho từng trường
   hợp, cuối cùng return 1 nếu có trường hợp FAIL, return 0 nếu tất cả PASS.
   Xem mẫu: code/tests/test_iv_setup.cpp

8. Giá trị mong đợi trong test phải lấy từ TÀI LIỆU (file PDF, RFC 4503) hoặc tự
   tính tay. Không được chạy code của mình rồi chép kết quả làm giá trị mong đợi
   (làm vậy thì code sai test vẫn PASS).

TIÊU CHÍ CHUNG KHI REVIEW
   - Build không warning, mingw32-make test PASS.
   - Code dễ đọc, comment tiếng Việt không dấu.
   - Mỗi test có tên rõ ràng, khi FAIL in ra giá trị mong đợi và giá trị thực tế.

      X0..X7 = 6E9E1D18 F5A54E5C F8FD49C6 9B94253F DCD14A79 1F32FA20 D2055921 53F371D0

VIỆC 4 - Test key setup
================================================================================
Nhánh: feature/<ten>-test-key-setup
File : code/tests/test_key_setup.cpp (đang trống), code/Makefile

Lưu ý: Makefile tự đổi tên chương trình thành test_key_init_app.exe vì Windows không
cho chạy file .exe có chữ "setup" mà không có quyền admin. Không cần làm gì thêm.

Cần làm:
1. Thêm test vector RFC 4503 Phụ lục A.1 thứ 3 (hiện CHƯA có trong dự án):
      key = 83 95 74 15 87 E0 C7 33 E9 E9 AB 01 C0 9B 00 43
   Tự tra RFC 4503 (https://www.rfc-editor.org/rfc/rfc4503) để lấy S[0], S[1], S[2].
   Dùng chế độ mặc định (ByteOrder::RFC).
2. Cùng một khóa, 2 đối tượng RabbitCipher khác nhau phải cho cùng 5 khối keystream.
3. Hiệu ứng thác (avalanche): với 100 khóa ngẫu nhiên, mỗi khóa đảo 1 bit ngẫu nhiên
   để được khóa thứ 2, đếm số bit khác nhau giữa 2 khối keystream đầu tiên (trên 128
   bit). Tỉ lệ TRUNG BÌNH của 100 lần phải nằm trong khoảng 48% - 52%. In tỉ lệ ra.
   (Không kiểm tra từng lần riêng lẻ: 1 khối chỉ có 128 bit nên từng lần dao động
   khoảng +-4.4%, code đúng vẫn có thể ra 38% hoặc 62%.)
4. Gọi setupKey 2 lần trên cùng một đối tượng: kết quả phải giống đối tượng mới chỉ
   gọi setupKey với khóa thứ 2.
5. Khóa K ở chế độ ByteOrder::RFC và khóa K đảo ngược thứ tự byte ở chế độ
   ByteOrder::PDF phải cho keystream là đảo ngược thứ tự byte của nhau.

Đạt yêu cầu khi: 5 nhóm test trên PASS, giá trị A.1 thứ 3 ghi rõ nguồn trong comment.
Gợi ý commit: khung test / vector RFC A.1 so 3 / test cung khoa / test avalanche /
              test setupKey 2 lan / test PDF va RFC
